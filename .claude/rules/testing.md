# 테스트 규칙

## 단위 테스트 (Vitest)

- 코드 파일 옆에 `<이름>.test.ts(x)`로 둔다.
- API를 거치는 로직(훅 등)은 MSW Node 서버로 같은 handler를 써서 테스트한다.
- 테스트 이름은 무엇을 확인하는지 한국어로 쓴다. (예: `검색 기록이 8개를 넘으면 가장 오래된 것을 지운다`)
- 대상: 화면과 분리된 로직 — 검색 기록 규칙, 가격 표시, 찜 store, API 응답 변환, 페이지 계산.
- 테스트를 통과시키려고 기대값을 바꾸지 않는다. 기대값이 틀렸다고 판단되면 근거와 함께 사용자에게 알린다.

## 브라우저 테스트 (Playwright)

- `e2e/`에 `<기능>.spec.ts`로 둔다.
- 사용자가 실제로 하는 동작(클릭, 키보드, Enter 검색, 한글 입력)으로 조작한다.
- 카카오 API는 MSW가 `src/mocks/fixtures/`의 고정 응답으로 돌려준다. (모킹을 켠 개발 서버로 실행) 실제 API 결과는 매번 바뀌어 as-is/to-be 영상 비교와 테스트 결과가 흔들리기 때문이다.
- Step 5(API 연결) 전에는 화면이 fixture를 직접 쓰므로 모킹이 필요 없다.
- `pnpm e2e:record`로 실행하면 영상이 `recordings/`에 저장된다. 영상은 PR 확인용이므로 사람이 보고 흐름을 이해할 수 있게 동작 사이에 너무 빠르게 넘어가지 않는다.
- `recordings/`는 커밋하지 않는다.
