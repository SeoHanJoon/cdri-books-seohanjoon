# ADR 작성

## 1. 번호와 파일 이름

- `docs/adr/`에서 가장 큰 번호를 찾아 +1 한다. 처음이면 `0001`.
- 파일 이름: `docs/adr/<4자리 번호>-<짧은-영문-kebab-case>.md` (예: `docs/adr/0003-wishlist-store.md`)

## 2. 내용

```markdown
# 0003. 찜 목록 저장 방식

- 상태: 채택
- 날짜: YYYY-MM-DD
- 관련 Step: Step 7

## 배경
어떤 문제가 있었나?

## 선택지
- A안: 장점 / 단점
- B안: 장점 / 단점

## 결정
무엇을 골랐고, 왜 골랐나?

## 결과
이 결정으로 좋아지는 점과 감수해야 하는 점
```

작성 규칙:

- **결정은 사용자의 것이다.** 사용자가 고른 선택과 그 이유를 적는다. 사용자가 아직 고르지 않았으면 상태를 `제안`으로 두고 결정 칸에 추천안을 "추천:"으로 적은 뒤 사용자에게 확인받는다.
- 쉬운 말로 짧게 쓴다. 한 섹션에 3~5줄이면 충분하다.
- 숫자 근거가 있으면 넣는다. (예: "번들 크기 +3KB", "요청 수 10회 → 1회")
- 날짜는 오늘 날짜를 쓴다.
- 이 ADR은 README의 "라이브러리 선택 이유"와 "강조하고 싶은 기능"의 근거로 쓰인다. 평가자가 읽는다고 생각하고 쓴다.

## 3. 기존 결정을 바꿀 때

- 이전 ADR을 지우거나 고쳐 쓰지 않는다.
- 새 ADR을 만들고, 이전 ADR의 상태를 `폐기 (→ 00NN)`로 바꾼다.

## 4. PLAN 연결

- `docs/PLAN.md` "4. 결정 필요 사항" 표에 해당 항목이 있으면 결정 칸을 `☑ [0003](adr/0003-wishlist-store.md)`처럼 바꾼다.
- 표에 없는 새 결정이면 표에 행을 추가한다.
