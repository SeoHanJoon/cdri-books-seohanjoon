# 0006. Step마다 브랜치와 PR로 진행하고, PR에 as-is / to-be 영상을 붙인다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: 전체

## 배경
제출물은 GitHub public 저장소다. 평가자가 결과 코드뿐 아니라 작업 과정과 판단 근거를 확인할 수 있으면 좋다.

## 선택지
- A안 main에 단계별 직접 커밋: 단순함 / 단계별 설명과 화면 변화를 남길 곳이 커밋 메시지뿐
- B안 Step 브랜치 + PR: PR 본문에 한 일, 완료 기준, ADR, 테스트 결과를 정리 / 브랜치·머지 관리가 늘어남
- B안 + 영상: PR 본문에 Playwright 녹화 영상을 첨부해 화면 변화를 바로 확인 / 녹화 시간이 추가됨

## 결정
B안 + 영상. Step 하나 = 브랜치 하나(`step-<번호>-<영문-이름>`) = PR 하나로 진행하고, 머지는 사람이 한다.
영상은 상황별로 정한다: 화면 변경 없음 → 없음 / 새 기능 → to-be만 / 기존 화면 변경 → as-is(main)와 to-be(PR)를 표로 나란히.
as-is는 base 브랜치 코드 위에서 이 PR의 테스트 파일을 실행해 같은 시나리오로 비교한다.

## 결과
- 평가자가 PR 목록만 봐도 Step별 작업 내용과 화면 변화를 확인할 수 있다.
- e2e는 카카오 API를 모킹해야 as-is와 to-be가 같은 데이터로 녹화된다. (0007, 0009)
- 커밋 메시지는 `<type>(step-N): <한국어 요약>` 형식을 쓴다.
