# 0052. 검색 입력 훅을 URL·전체 검색·상세 검색 세 개로 나누고, 조합은 페이지에서 한다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 7

## 배경
Step 7에서 상세 검색을 붙이고 나니 `useSearchInput` 한 훅이 네 가지 일을 맡았다. ([0049](0049-search-page-split.md), [0051](0051-detail-search-execution.md))
URL 읽기·쓰기, 메인 입력창을 URL에 맞추기(state 3개), 전체 검색과 기록, 상세 검색 기본값과 실행이다.
상호 초기화("상세 검색하면 메인 입력창을 비운다")가 훅 안에 숨어 있어 읽기 어려웠다.
또 검색한 뒤 입력창에 친 글자를 그대로 둘지(`"  하루키 "`), URL 값으로 맞출지(`"하루키"`) 정해야 했다.

## 선택지
- 나누는 방법
  - A안 훅 3개(`useSearchUrl`, `useMainSearch`, `useDetailSearch`), 조합은 페이지: 훅마다 일이 하나, 상호 초기화가 페이지 코드에 보임 / 파일 2개 증가
  - B안 메인·상세 훅 2개가 각자 URL을 읽음: 페이지가 단순 / URL 해석과 "같은 URL이면 건너뛰기"가 두 곳에 중복
  - C안 입력창 동기화 부분만 작은 훅으로 뽑기: 변경이 가장 작음 / 상세 검색은 여전히 같은 훅에
- 검색 후 입력창 글자
  - A안 URL 값(앞뒤 공백 제거)으로 맞춤: 입력창이 실제로 검색한 값을 보여줌 / 친 공백이 사라짐
  - B안 친 그대로 둠: 지금 동작 그대로

## 결정
둘 다 A안. (사용자 선택)
- `useSearchUrl()`은 `{ parsed, key, push }`를 준다. `push`는 같은 URL이면 아무것도 하지 않고 `null`, 바꿨으면 새 URL 키를 돌려준다.
- 페이지는 `useSearchUrl()` 결과를 `useMainSearch`, `useDetailSearch`에 그대로 넘긴다. 메인 입력창이 "URL이 바뀌었는지" 알려면 `key`도 필요해서 `parsed`, `push`만 넘기지 않았다.
- 상세 검색 `onSubmit`에서 페이지가 `main.clear()` → `detail.submit()`을 부른다. 상호 초기화가 페이지 한 곳에 보인다. ([0036](0036-detail-search-component.md))

처음에는 A안으로 "검색한 글자를 지키는 state(`submittedKey`)"도 없애려 했는데, 기존 브라우저 테스트 2개가 실패해서 남겼다.
이 state는 공백 처리용이 아니었다. `setSearchParams`는 URL을 한 박자 늦게 바꾸는데, 직접 보낸 URL이 도착할 때 입력창을 덮어쓰면 그 사이 친 글자가 사라진다.
그래서 이름을 `pendingKey`(보냈지만 아직 도착하지 않은 URL)로 바꿔 남기고, 공백 제거는 검색할 때 입력창을 직접 맞추는 것으로 했다.

## 결과
- 훅 셋이 각각 15~35줄이고, 페이지에서 세 훅의 관계가 바로 보인다.
- 검색하면 입력창이 공백을 지운 검색어로 바뀐다. 같은 URL이라 이동하지 않는 경우에도 같다.
- 0049의 "`useSearchInput`이 URL 해석·입력창·검색을 맡는다"는 이 결정으로 바뀐다. `SearchResults`, `LoadMoreFooter`는 그대로다.
