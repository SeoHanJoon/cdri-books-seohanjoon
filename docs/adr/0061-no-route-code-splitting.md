# 0061. 라우트 단위 코드 분할은 하지 않는다 (측정 후 결정)

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 9

## 배경
[0058](0058-route-code-splitting.md)은 찜·NotFound 페이지만 `lazy`로 나누기로 했다. 구현해서 운영 빌드를 재 보니 예상과 달랐다.

| | 메인 JS (gzip) | 따로 받는 JS | 첫 화면에 받는 양 |
|---|---|---|---|
| 나누지 않음 | 119.39KB | — | 119.39KB |
| 찜·NotFound `lazy` | 119.99KB | 찜 0.61KB | 119.99KB (+0.6KB) |

- 파일을 나누면 Vite가 나눈 파일을 미리 받는 코드(preload helper)를 메인 JS에 넣는다. 이 코드가 빠지는 찜 페이지보다 크다.
- NotFound는 도서 검색 페이지가 잘못된 `target`일 때 직접 import해서([0010](0010-not-found.md)) 나뉘지 않는다. 빌드가 `INEFFECTIVE_DYNAMIC_IMPORT` 경고를 낸다.

## 선택지
- A안 나누지 않음: 첫 화면 JS가 가장 작음 / 페이지가 커지면 다시 판단해야 함
- B안 찜만 `lazy`: 페이지가 늘어도 메인 JS에 쌓이지 않는 구조 / 지금은 첫 화면 JS +0.6KB
- C안 NotFound도 나뉘게 도서 검색 페이지 구조 변경: 0058 그대로 / 코드가 복잡해지는데 줄어드는 양 0.3KB 안팎, 첫 화면 JS는 여전히 커짐

## 결정
A안. (사용자 선택)
나눠서 얻는 것이 없고 첫 화면만 무거워진다. JS의 대부분은 react-dom·react-router·query-core라 페이지 단위로 나눌 몫이 작다.
[0014](0014-react-router-data-mode.md)의 데이터 모드는 그대로 둔다. 페이지가 커지면 라우트에 `lazy`만 붙이면 된다.

## 결과
- 라우터 코드가 바뀌지 않는다.
- 다시 판단할 기준: 나눌 페이지가 preload helper보다 확실히 커질 때(gzip 수 KB 이상).
