# 0007. 테스트는 Vitest(로직)와 Playwright(화면)로 나눈다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 1 이후 전체

## 배경
과제 필수 항목은 아니지만, 검색 기록 규칙(최대 8개, 오래된 것부터 삭제), 가격 표시(할인가 없으면 미노출), 찜 store처럼 규칙이 있는 로직은 테스트로 지키는 것이 유지보수에 유리하다.
또 PR 영상 녹화(0006)에 브라우저 자동화 도구가 필요하다.

## 선택지
- A안 Vitest + Playwright: 로직은 빠른 단위 테스트, 화면 흐름은 실제 브라우저 테스트 + 영상 녹화 / 도구 2개 설정
- B안 Playwright만: 설정 하나 / 로직 규칙의 경계값(8개, 9개째 등)을 화면으로만 검증해야 해서 느리고 실패 원인을 찾기 어려움

## 결정
A안. Vitest는 Vite 설정을 그대로 공유해 추가 설정이 거의 없다.
API 응답은 MSW가 고정 fixture(`src/mocks/fixtures/`)로 돌려준다. 실제 API 결과는 매번 바뀔 수 있어 테스트와 영상 비교가 흔들리기 때문이다. ([0009](0009-screens-first-msw.md))

## 결과
- 화면과 분리된 로직은 코드 옆 `*.test.ts`로, 사용자 흐름은 `e2e/*.spec.ts`로 검증한다.
- e2e는 API 키 없이도 실행된다.
- 실제 API와의 연동은 e2e가 아니라 개발 중 수동 확인으로 검증한다.
