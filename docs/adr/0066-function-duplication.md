# 0066. 팝업 닫기는 useDismiss 훅으로 묶고, 검색어 공백은 들어오는 곳에서만 정리한다

- 상태: 채택
- 날짜: 2026-11-28
- 관련 Step: Step 11

## 배경
기능이 겹치는 함수를 점검했다.
1. "바깥이나 Esc로 닫기"를 세 곳이 각자 구현한다.
   - 검색 기록 드롭다운: 포커스가 밖으로 나가거나 Esc
   - 상세 검색 팝업: 바깥 클릭, Esc(포커스를 버튼으로 돌림), 포커스가 밖으로 나감
   - Select: 포커스가 밖으로 나가거나 Esc. Esc는 목록만 닫고 팝업까지 닫히지 않게 막는다
2. 검색어 앞뒤 공백 정리(`trim`)가 5곳에 있다: `parseSearchParams`, `toSearchParams`, `useMainSearch`, `searchHistoryStore.add`, 상세 검색의 빈 값 검사. 상세 검색은 공백이 붙은 채로 넘기고, URL을 만들 때 정리된다.
3. isbn으로 찾기·중복 빼기도 4곳(검색 결과 중복 제거, 찜 페이지 합치기, 찜 토글, 찜 여부)에 있다.

## 선택지
- 1: A안 `useDismiss(ref, onDismiss)` 훅 / B안 유지
- 2: A안 들어오는 곳(URL 읽기, 사용자 입력)에서만 정리 / B안 공용 함수만 만들고 위치 유지 / C안 유지
- 3: A안 공용 함수 / B안 유지

## 결정
1-A, 2-A, 3-B. (사용자 선택)
1. `useDismiss`는 열려 있는 동안 바깥 클릭, Esc, 포커스가 바깥 요소로 옮겨 가는 것을 감지해 `onDismiss(이유)`를 부른다. 포커스를 어디로 돌릴지는 쓰는 쪽이 이유를 보고 정한다. 검색 기록 드롭다운과 상세 검색 팝업에 쓴다. Select는 Esc 동작이 달라 그대로 둔다.
   - 지금 두 팝업은 안쪽 빈 여백을 눌렀을 때만 다르다. 드롭다운은 닫히고 상세 검색은 닫히지 않는다. 드롭다운의 빈 여백은 기록 줄 위(7px)·아래(16px) 띠와 입력 줄의 돋보기 아이콘·양옆 여백이다.
     - 원인: 포커스를 받지 못하는 곳을 누르면 포커스가 `body`로 가고 `relatedTarget`(다음 포커스 대상)이 `null`이 된다. 바깥 빈 곳을 눌러도 안쪽 여백을 눌러도 똑같이 `null`이다. 드롭다운은 포커스 이동만 보고 닫아서 둘을 구별하지 못한다. 상세 검색은 클릭은 누른 위치(`pointerdown`)로 따로 보고 `null`은 무시해서 안쪽 여백에서는 닫히지 않는다.
   - 드롭다운도 상세 검색처럼 안쪽 빈 여백을 눌러도 닫히지 않게 바꾼다. (사용자 선택) 두 팝업의 닫기 규칙이 같아져 훅에 옵션이 필요 없다.
   - 닫지 않기만 하면 드롭다운은 열려 있는데 포커스는 `body`에 있게 된다(글자 입력이 안 되고 Tab이 엉뚱한 곳에서 시작). 그래서 검색 상자 안에서 입력창·버튼이 아닌 곳의 `mousedown` 기본 동작을 막아 포커스를 입력창에 남긴다. Select 목록이 이미 쓰는 방식이다.
2. 정리하는 곳은 두 곳이다. URL을 읽을 때는 `parseSearchParams`, 사용자가 입력했을 때는 `useMainSearch`·`useDetailSearch`가 정리한다. 안쪽의 `toSearchParams`와 `searchHistoryStore.add`는 정리된 값을 믿는다. 상세 검색 팝업의 빈 값 검사는 정리가 아니라 입력 검사라 남긴다.
3. 넷은 목적이 달라(먼저 온 것 남기기, 새로 찜한 것 앞에 붙이기, 넣고 빼기, 찾기) 공용 함수로 얻는 것이 적다. 유지한다.

## 결과
- 닫기 규칙이 한 곳에 있고, 두 팝업이 같은 규칙으로 닫힌다(바깥 클릭, Esc, 포커스가 바깥 요소로 이동).
- 검색 기록 드롭다운 안의 빈 여백을 누르면 지금은 닫히지만, 바꾼 뒤에는 열린 채 입력창 포커스가 남는다. 동작 변경이라 e2e를 더하고 PR에 as-is/to-be 영상을 붙인다.
- 공백 규칙이 "들어올 때 한 번"으로 분명해진다. store 단위 테스트의 "앞뒤 공백을 지우고 넣는다"는 규칙이 옮겨 가므로 "빈 검색어는 넣지 않는다"로 줄이고, 공백 정리는 e2e로 확인한다.
