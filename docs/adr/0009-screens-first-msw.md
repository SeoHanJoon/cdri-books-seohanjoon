# 0009. 화면 구성을 먼저 끝내고 API는 MSW와 함께 연결한다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 3 ~ Step 8

## 배경
UI 구현력과 디자인 완성도가 첫 번째 평가 항목이다. 화면을 Figma와 먼저 맞춰 확정한 뒤 데이터만 바꿔 끼우면, 화면 작업과 데이터 작업이 섞이지 않는다.
화면을 만들 때도, API를 연결한 뒤 테스트·PR 영상을 만들 때도 같은 가짜 데이터가 필요하다.

## 선택지
- 작업 순서
  - A안 화면 먼저: 화면 구성(Step 3~4)을 끝낸 뒤 API·기능(Step 5~8) 연결 / 화면 단계에서는 실제 데이터 흐름을 확인하지 못함
  - B안 기능별로 화면 + API 함께: 기능 하나가 끝까지 동작 / 화면 완성도 점검이 기능마다 흩어짐
- 가짜 데이터 공급
  - A안 MSW: 앱은 실제 `fetch`를 호출하고 네트워크 단계에서만 응답을 바꿈. 개발 서버·Vitest·Playwright가 handler 하나를 공유. 지연·에러·0건 상황을 쉽게 재현 / 의존성과 `public/mockServiceWorker.js` 추가, 운영 빌드에서 제외 처리 필요
  - B안 Playwright `page.route`: 설정 없음 / e2e에서만 쓸 수 있어 개발 중 화면 확인·단위 테스트용 가짜 데이터를 따로 만들어야 함
  - C안 화면 단계부터 MSW: 처음부터 실제 요청 흐름 / fetch 함수와 React Query 훅을 먼저 만들어야 해서 사실상 API 연결을 앞당김

## 결정
작업 순서는 A안(화면 먼저), 가짜 데이터는 A안(MSW)을 Step 5(API 연결)부터 쓴다.
화면 단계(Step 3~4)는 카카오 응답 형식의 fixture JSON(`src/mocks/fixtures/`)을 직접 넣고, Step 5부터 MSW handler가 같은 fixture를 응답으로 돌려준다. fixture는 버려지지 않고 끝까지 재사용된다.
MSW는 `VITE_API_MOCKING=enabled`일 때만 개발 서버에서 시작하고 운영 빌드에는 포함하지 않는다.

## 결과
- 화면 단계 PR은 Figma와 화면만 비교하면 되고, 기능 단계 PR은 데이터 흐름만 보면 된다.
- 테스트와 PR 영상(0006)이 API 키 없이 항상 같은 데이터로 실행된다.
- 화면 단계에서 만든 "카카오 응답 → 컴포넌트 props 변환 함수"를 API 연결 때 그대로 쓴다.
- MSW 최신 버전(v3)의 설정 방법은 설치 시 공식 문서로 확인한다.
