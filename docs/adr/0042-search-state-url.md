# 0042. 실행 중인 검색은 URL이 기준이고, 검색할 때마다 기록을 쌓는다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 5, Step 6, Step 7

## 배경
검색 조건(`?query=&target=`)이 새로고침·뒤로가기 뒤에도 남아야 한다. ([0010](0010-not-found.md))
SearchBox의 입력창 글자는 페이지가 관리한다. ([0027](0027-searchbox-controlled.md)) 입력 중인 글자와 실행 중인 검색을 어디에 둘지 정해야 한다.

## 선택지
- A안 URL이 기준 + push: 실행 중인 검색은 URL에서만 읽음, 뒤로가기로 이전 검색에 돌아감 / 뒤로가기 때 입력창 글자를 URL에 맞추는 처리 필요
- B안 URL이 기준 + replace: 새로고침은 유지 / 뒤로가기가 검색 전 페이지로 가서 이전 검색이 사라짐
- C안 페이지 state가 기준, URL에 복사: 익숙한 `useState` / 같은 값이 두 곳에 있어 맞추는 코드가 늘고 어긋날 수 있음

## 결정
A안. (사용자 선택)
- 실행 중인 검색은 `useSearchParams`로 URL에서만 읽는다. 따로 state에 복사하지 않는다.
- 검색하면 URL을 바꾸며 기록을 하나 쌓는다. 지금 URL과 같은 검색이면 쌓지 않는다.
- 입력창 글자는 페이지 state다. URL이 바뀌면(뒤로가기 등) 입력창도 URL의 검색어로 맞춘다.
- 검색어는 앞뒤 공백을 지워서 URL에 넣는다. 빈 검색어는 초기 화면이다.

## 결과
- 검색 결과 주소를 그대로 공유하거나 북마크할 수 있다.
- Step 7의 전체 ↔ 상세 상호 초기화는 URL을 한 번 바꾸는 것으로 끝난다. 두 검색이 한 URL에 같이 있을 수 없다.
- React Query 캐시가 같은 검색을 기억하므로, 뒤로가기 때 다시 요청하지 않고 바로 이전 결과를 보여준다.
