# 0058. 라우트 분할은 찜·NotFound 페이지만 한다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 9

## 배경
[0014](0014-react-router-data-mode.md)에서 라우트 `lazy`로 코드를 나누려고 데이터 모드를 골랐다.
운영 빌드 JS는 gzip 119KB 한 파일이다. 대부분 react-dom, react-router, query-core이고, `src/pages`는 압축 전 소스로 5.6KB다. 페이지끼리 쓰는 `BookList` 등은 공통이라, 어떻게 나눠도 줄어드는 양은 1KB 안팎이다.

## 선택지
- A안 찜·NotFound만 `lazy`: 첫 화면(도서 검색) 속도 그대로 / 효과가 작음
- B안 모든 페이지 `lazy`: 구조가 일관됨 / 첫 방문 때 메인 JS 다음에 도서 검색 JS를 한 번 더 받아야 해서 첫 화면이 늦어짐
- C안 나누지 않음: 코드 그대로 / 페이지가 늘어나도 한 파일에 계속 쌓임

## 결정
A안. (사용자 선택)
첫 화면은 늦추지 않고, 처음에 안 보는 페이지만 이동할 때 받는다. 효과가 작다는 점은 위 숫자로 남긴다.
NotFound는 도서 검색 페이지가 잘못된 `target`일 때도 그리므로([0010](0010-not-found.md)), 이 경우에는 메인 JS에 남는다. 분할되는 것은 없는 경로(`*`) 라우트 쪽이다.

## 결과
- 페이지가 늘어나도 메인 JS에 쌓이지 않는 구조가 된다.
- 찜 탭을 처음 누를 때 작은 JS 파일 하나를 받는 동안 이동이 잠깐 늦어진다.
