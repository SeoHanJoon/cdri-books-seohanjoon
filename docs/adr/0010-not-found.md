# 0010. 잘못된 경로와 잘못된 검색 조건은 "존재하지 않는 페이지" 화면으로 처리한다

- 상태: 일부 폐기 (`NoData` 재사용 → 0041)
- 날짜: 2026-11-27
- 관련 Step: Step 1, Step 4, Step 5

## 배경
검색 조건을 URL 쿼리(`?query=&target=`)에 담기 때문에, 주소를 직접 고치거나 잘못된 링크로 들어오면 허용되지 않은 `target`(예: `?target=foo`)이 들어올 수 있다. 화면의 상세 검색 Select와 검색 기록에서는 잘못된 값이 나오지 않는다.
없는 경로(예: `/abc`)도 처리 방법이 필요하다. 두 경우 모두 Figma에는 정의되어 있지 않다.

## 선택지
- A안 "존재하지 않는 페이지입니다." 화면: 잘못된 요청임을 분명히 알림, 잘못된 조건으로 API를 호출하지 않음 / 검색어가 있어도 결과를 보여주지 않음
- B안 `target`을 무시하고 전체 검색: 검색어를 살림 / 사용자가 요청한 것과 다른 검색이 조용히 실행됨
- C안 제목(`title`) 검색으로 대체: 상세 검색 유지 / 사용자가 고르지 않은 조건으로 검색됨

## 결정
A안. 잘못된 요청을 다른 검색으로 바꿔 실행하지 않고, 없는 경로와 같은 화면으로 일관되게 처리한다.
- URL을 읽는 지점 한 곳에서 `target`을 허용 값(`title` / `person` / `publisher`)으로 검증한다. 검증을 통과한 값만 `SearchTarget` 타입이 되어 API 함수에 들어갈 수 있다.
- 화면은 Figma에 없으므로 기존 컴포넌트로 구성한다: Header 유지, `NoData`("존재하지 않는 페이지입니다."), 도서 검색으로 돌아가는 버튼.

## 결과
- 잘못된 조건으로는 API 요청이 나가지 않는다.
- 검증 로직이 한 곳에 모여 단위 테스트하기 쉽다.
- 그래도 API가 에러를 돌려주는 경우(키 오류, 서버 오류 등)는 Step 5의 에러 상태 UI가 처리한다.
