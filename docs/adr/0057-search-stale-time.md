# 0057. 검색 결과는 5분 동안 새 데이터로 본다 (staleTime 5분)

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 9

## 배경
TanStack Query 기본값(`staleTime: 0`)은 받은 데이터를 곧바로 오래된 것으로 본다. 그래서 브라우저 탭으로 돌아오거나, 찜 페이지에 다녀오거나, 뒤로가기할 때마다 다시 요청한다.
무한 스크롤 목록은 불러온 페이지를 전부 차례로 다시 받는다. 10페이지까지 봤으면 10번이다.
책 정보는 자주 바뀌지 않고, 카카오 API에는 일일 호출 한도가 있다.

## 선택지
- A안 5분: 짧은 왕복은 요청 없음, 5분이 지나면 캐시를 먼저 보여 주고 뒤에서 새로 받음 / 5분 안의 가격 변동은 늦게 보임
- B안 `Infinity`: 요청이 가장 적음 / 새로고침 전까지 바뀐 정보가 반영되지 않음
- C안 기본값 유지: 늘 최신 / 돌아올 때마다 불러온 페이지 수만큼 요청

## 결정
A안. (사용자 선택)
검색 훅(`useBookSearch`)에만 `staleTime`을 둔다. 앱의 서버 데이터가 도서 검색 하나뿐이고, 값의 근거가 "책 정보는 자주 바뀌지 않는다"는 이 데이터의 성질이기 때문이다.

## 결과
- 5분 안에 같은 검색으로 돌아오면 요청이 0번이다.
- 캐시를 지우는 시간(`gcTime`)은 기본 5분 그대로다. 안 보는 검색 결과는 5분 뒤 메모리에서 지워진다.
