# 0051. 상세 검색 실행: 빈 검색어는 팝업에 남기고, 개발 데이터는 실제 저자명 검색 응답

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 7

## 배경
팝업 '검색하기'로 상세 검색을 실행한다. 정해야 할 것이 세 가지 있었다.
- 상세 검색어가 비어 있을 때 '검색하기'를 누르면 어떻게 할지. 전체 검색은 빈 검색어면 초기 화면으로 간다. ([0042](0042-search-state-url.md))
- MSW handler가 `target`이 붙은 요청에는 늘 0건을 줘서, 개발 서버에서 상세 검색 결과를 볼 수 없었다.
- 상세 검색 로직을 어디에 둘지.

## 선택지
- 빈 검색어
  - A안 초기 화면으로 가고 팝업 닫기: 전체 검색과 규칙이 같음 / 실수로 누르면 보던 결과가 사라짐
  - B안 아무것도 하지 않고 팝업을 연 채 검색어 입력창에 포커스: 결과가 실수로 사라지지 않음 / "검색하기는 팝업을 닫는다"에 예외가 하나 생김
  - C안 버튼 비활성화: 누를 수 없어 헷갈리지 않음 / 시안에 비활성 버튼 스타일이 없음
- 개발 데이터
  - A안 실제 카카오 응답 저장(`target=person`, `query=무라카미 하루키` 1페이지): 조건에 따라 결과가 달라지는 것이 보임 / fixture 파일 1개 추가
  - B안 `target`을 무시하고 검색어 fixture 그대로: 파일이 늘지 않음 / 조건이 전달되는지 화면으로 확인할 수 없음
  - C안 지금처럼 0건: 결과가 나오는 상세 검색을 시연할 수 없음
- 로직 위치
  - A안 `useSearchInput`에 `submitDetail`, `detailDefault` 추가: URL과 입력창을 다루는 곳이 하나라 상호 초기화가 한 곳에 모임 / 훅이 커짐
  - B안 `useDetailSearch` 분리: 훅마다 맡은 일이 하나 / 두 훅이 URL을 각자 읽고 씀

## 결정
빈 검색어 B안, 개발 데이터 A안, 로직 위치 A안. (사용자 선택. 로직 위치는 A안으로 해 보고 복잡해지면 나누기로 했고, 훅이 55줄 정도라 A안을 유지했다)
- 빈 검색어 판단은 앞뒤 공백을 지운 뒤에 한다. 기존 결과를 지우는 것은 전체 검색 쪽 빈 Enter로만 한다.
- 저자명 검색 "무라카미 하루키"는 780건이다. 전체 검색 866건과 건수가 달라서 조건이 실제로 전달됐는지 화면에서 바로 보인다. 무한 스크롤은 같은 코드라 1페이지만 저장했다.
- 상세 검색은 URL을 `?query=&target=`으로 바꾸고, 검색 기록에는 넣지 않는다. ([0004](0004-search-history-scope.md))
- 팝업 기본값은 URL에서 계산한다(`toDetailSearchCondition`). 뒤로가기하면 팝업 기본값도 그 검색의 조건으로 돌아간다.
- 같은 조건으로 다시 검색하면 URL이 그대로라 동기화가 일어나지 않는다. 그래서 상세 검색을 실행할 때 메인 입력창은 직접 비운다.

## 결과
- 팝업에서 실수로 빈 채로 눌러도 보던 결과가 유지된다.
- 구현 중 입력창 동기화 기준을 "URL의 전체 검색어"에서 "URL 전체"로 바꿨다. 상세 검색끼리 뒤로가기하면 전체 검색어는 계속 `''`라서, 쓰다 만 글자가 남는 문제가 있었다. 브라우저 테스트로 다시 잡는다.
- MSW handler는 `target`·검색어 조합으로 fixture를 고른다. 저장하지 않은 조합은 0건이다.
