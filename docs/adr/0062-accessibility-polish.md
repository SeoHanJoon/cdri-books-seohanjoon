# 0062. 접근성 보완: 빈 상세 검색어 안내, 버튼과 책 제목 연결, 건수 알림

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 9

## 배경
Step 9 점검 결과, `aria-expanded`(상세보기·상세검색·검색 조건)와 키보드 조작은 이미 되어 있었다. 빈 곳은 다섯 가지였다.
1. 상세 검색어가 비어 '검색하기'가 막혀도 입력창으로 포커스만 갈 뿐 이유를 읽어 주지 않는다. ([0051](0051-detail-search-execution.md))
2. 행마다 '상세보기'·'구매하기'·'찜하기'가 같은 이름이라, 버튼만 옮겨 다니면 어느 책인지 모른다.
3. 구매하기가 새 탭으로 열린다는 것을 미리 알리지 않는다.
4. 검색해도 "총 N건"이 바뀐 것을 읽어 주지 않는다.
5. 검색 입력창에 포커스 표시가 없다(`outline-none`).

## 선택지
- 빈 검색어 안내
  - A안 숨긴 안내 + `aria-invalid`: 화면 그대로, 포커스가 오면 "잘못됨, 검색어를 입력해 주세요"를 읽음 / 이미 입력창에 있을 때(Enter)는 다시 읽지 않을 수 있음
  - B안 보이는 안내 문구: 누구나 봄 / 시안에 없는 UI
  - C안 `role="alert"`: 곧바로 읽음 / 포커스 이동 때 읽는 입력창 이름과 겹쳐 끊길 수 있음
- 검색창 포커스 표시: `:focus-visible`은 버튼에서는 키보드로 왔을 때만 켜지지만, 텍스트 입력창에서는 마우스로 눌러도 켜진다(Chromium·WebKit에서 확인, CSS 표준의 기준). 그래서 "Tab으로 왔을 때만"은 CSS로 안 된다.
  - A안 포커스되면 항상 테두리 / B안 마지막 조작이 키보드였는지 JS로 기억 / C안 하지 않음

## 결정
(사용자 선택)
- 1은 A안. 입력창에 `aria-invalid`와 숨긴 안내(`aria-describedby`)를 붙이고, 글자를 치면 푼다.
- 2를 고친다. 세 버튼에 `aria-describedby`로 그 행의 책 제목을 연결한다. 이름은 그대로라 "상세보기" 같은 음성 명령도 그대로 된다.
- 3은 하지 않는다.
- 4를 고친다. `SearchCountText`에 `aria-live="polite"`를 붙여, 숫자가 바뀌면 "도서 검색 결과 총 866건"을 통째로 읽는다. 불러오는 동안에는 직전 건수를 그대로 두므로([0047](0047-count-while-loading.md)) 끝났을 때 한 번만 읽는다.
- 5는 C안. 처음에는 A안으로 테두리를 그렸다. 하지만 마우스로 눌러도 보이는 것이 자연스럽지 않았고, "Tab으로 왔을 때만" 보이게 하려고 스크립트를 더하고 싶지는 않았다(사용자 판단). 시안대로 표시하지 않는다.

## 결과
- 화면 낭독기 사용자가 막힌 이유, 버튼의 책, 검색 건수를 들을 수 있다.
- 검색 입력창은 시안대로 포커스 테두리가 없다. 키보드 사용자는 깜빡이는 커서로 위치를 알고, 검색 기록이 있으면 드롭다운이 열린다.
- 빈 검색어에서 입력창에 있는 채로 Enter를 누르면, 포커스가 움직이지 않아 안내를 바로 읽지 않을 수 있다. 다시 입력창으로 들어오면 읽는다.
