# 0055. 찜 페이지의 보여줄 목록 규칙은 순수 함수로 단위 테스트하고, 10권씩 늘리기는 브라우저로 확인한다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 8

## 배경
[0053](0053-wishlist-store-and-page.md)은 "10권씩 자르는 로직은 작은 훅으로 빼서 단위 테스트한다"고 정했다.
만들어 보니 Vitest는 Node 환경이고 React를 그릴 도구(`@testing-library/react`, jsdom)가 없어 훅을 직접 돌릴 수 없다. 또 자르는 로직은 `slice(0, count)`와 `count + 10`뿐이라 지킬 규칙이 거의 없다.
규칙다운 규칙은 찜 페이지에 보여줄 목록이다. 해제한 책은 페이지를 떠날 때까지 제자리에 남고, 다른 탭에서 새로 찜한 책은 맨 위에 더한다.

## 선택지
- A안 보여줄 목록 규칙은 `src/lib/`의 순수 함수로 Vitest, 10권씩 늘리기는 작은 훅으로 두고 Playwright: 의존성 추가 없음 / 0053 문구를 고쳐야 함
- B안 훅 테스트 도구 추가: 0053 그대로 / 개발 의존성 2개와 Vitest 환경 설정이 늘고, "화면은 Playwright"([0045](0045-api-layer-and-tests.md))와 겹침
- C안 브라우저 테스트만: 코드가 가장 적음 / "다른 탭에서 새로 찜한 책" 같은 경우를 브라우저로 재현하기 번거로움

## 결정
A안. (사용자 선택)
- `mergeShownBooks(shown, current)`: 지금 찜 목록 중 처음 보는 책만 맨 앞에 더하고, 이미 보여준 책은 해제됐어도 그 자리에 둔다. 더할 책이 없으면 받은 배열을 그대로 돌려줘서 페이지가 상태를 다시 바꾸지 않는다.
- `usePagedList(items, pageSize)`: 보여줄 개수를 `pageSize`에서 시작해 `loadMore`마다 늘린다. 12권을 찜하고 찜 페이지에서 10권 → 스크롤 → 12권이 되는지 Playwright로 확인한다.
- 0053의 다른 결정(저장 모양, 순서, 해제 동작, 10권씩 늘리기)은 그대로다.

## 결과
- 찜 페이지에서 가장 헷갈리기 쉬운 규칙이 빠른 단위 테스트로 지켜진다.
- 훅 자체는 단위 테스트가 없고, 브라우저 테스트가 대신한다.
