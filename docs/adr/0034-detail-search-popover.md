# 0034. 상세 검색 팝업과 조건 Select는 라이브러리 없이 직접 만든다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 3, Step 7

## 배경
'상세검색' 버튼 아래에 팝업(360×160)이 열리고, 안에 검색 조건 Select(제목 / 저자명 / 출판사)와 검색어 입력, '검색하기' 버튼이 있다. (`18:608`, `744:156`)
시안의 Select 목록은 흰 상자에 그림자이고, 고른 항목은 목록에서 빠진다.

## 선택지
번들 크기는 각 라이브러리를 minify + gzip으로 묶어 잰 값이다. 현재 앱 JS는 106KB.
- A안 Headless UI (Popover + Listbox): +39KB(앱의 37%), 바깥 클릭·Esc·포커스 복귀·방향키 기본 제공, 코드 가장 짧음
- B안 Radix (Popover + Select): +33KB, 패키지 2개, 고른 항목을 목록에서 빼려면 우회 필요
- C안 Floating UI: +21KB, 위치·닫기만 해결하고 Select는 직접 작성
- D안 직접 구현: 약 +2KB, 접근성 동작을 직접 테스트로 지켜야 함
- Select만 놓고 보면 기본 `<select>`도 있지만, 펼친 목록이 운영체제 모양이라 시안과 다르다.

## 결정
D안. (사용자 선택) 팝업 하나, 선택지 3개 Select를 위해 앱 JS를 37% 늘리는 것은 과하다. 필요한 동작이 정해져 있어 테스트로 모두 지킬 수 있고, 코드 전체를 설명할 수 있다.
- 팝업: 바깥 클릭·Esc·X·'검색하기'로 닫고, 닫히면 포커스를 '상세검색' 버튼으로 돌린다.
- Select: 클릭·Enter·Space로 열고, ↑↓로 이동, Enter로 고르고, Esc는 목록만 닫는다(팝업은 유지).
- 값 관리: 조건과 검색어는 팝업 안에서 관리하고, 열 때마다 페이지가 준 `defaultValue`로 시작해 '검색하기' 때 `onSubmit({ target, keyword })`로 알린다. 전체 검색 시 상세 조건 초기화(Step 7)는 페이지가 넘기는 값을 비우는 것으로 끝난다.
- 위치: 넓은 화면은 시안대로 버튼 15px 아래 가운데. 화면 밖으로 넘치는 좁은 화면은 SearchBox 오른쪽 끝에 맞추고 너비를 `min(360px, 화면 − 32px)`로 줄인다.

## 결과
- 의존성 없이 약 +2KB로 끝난다.
- Esc가 Select와 팝업을 한꺼번에 닫는 실수 같은 것을 직접 막아야 한다. 동작마다 브라우저 테스트를 둔다.
