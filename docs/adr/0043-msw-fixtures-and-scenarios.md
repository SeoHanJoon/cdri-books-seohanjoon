# 0043. MSW는 실제 응답 3페이지를 돌려주고, 지연·에러는 검색어로 고른다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 5

## 배경
Step 3 fixture는 "무라카미 하루키" 1페이지 10권뿐인데 응답은 `is_end: false`(총 866건)다. ([0030](0030-fixture-real-response.md)) 무한 스크롤을 보여주려면 다음 페이지가 필요하다.
로딩·에러 화면도 개발 서버, Playwright, PR 영상에서 재현할 수 있어야 한다.

## 선택지
- 다음 페이지
  - A안 실제 page 2, 3 저장: 실제 데이터 그대로 / 총 866건인데 30권에서 끝남
  - B안 1페이지를 복제해 생성: 끝없이 만들 수 있음 / 같은 표지·소개가 반복돼 가짜 티가 남
  - C안 결과 20~30건인 다른 검색어: 건수와 `is_end`가 실제와 맞음 / 시연 검색어가 둘이 됨
- 시나리오 고르기
  - A안 검색어로 고름: 0030 방식 그대로, 손으로 재현하기 쉽고 영상에 보임 / 검색어 몇 개를 예약
  - B안 `window`에 worker 노출, e2e가 handler 교체: 검색어 예약 없음 / 손으로 재현하려면 콘솔 필요
  - C안 `?mock=error` 같은 URL 파라미터: 검색어와 분리 / 앱 URL 처리에 개발용 분기가 섞임

## 결정
다음 페이지 A안, 시나리오 A안. (사용자 선택)
- `page` 1~3은 저장한 실제 응답이고, 3페이지 응답은 handler가 `is_end: true`로 바꿔 목록을 끝낸다.
- 검색어 "에러"는 500 응답, "느린 검색"은 3초 뒤 결과를 준다. 그 밖의 검색어는 0건이다.
- 평소 응답에는 MSW 기본 지연(브라우저 100~400ms, Node 5ms)을 둔다.

## 결과
- 키 없이 결과·무한 스크롤·0건·로딩·에러를 모두 개발 서버에서 볼 수 있다.
- 예약 검색어는 MSW handler에만 있고 앱 코드에는 없다. 운영 빌드에는 MSW가 들어가지 않는다.
- 건수(866)와 실제로 불러오는 책 수(30)가 다르다. 가짜 데이터의 한계로 받아들인다.
