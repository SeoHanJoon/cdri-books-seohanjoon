# 0036. 상세 검색은 버튼·팝업을 한 컴포넌트에 두고, 전체 검색과 입력을 공유하지 않는다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 3, Step 7

## 배경
팝업은 SearchBox 안의 '상세검색' 버튼 바로 아래에 열린다. ([0034](0034-detail-search-popover.md))
검색어 입력창이 메인과 팝업 두 곳이 되고, Figma 주석은 "전체 검색과 상세 검색은 동시에 진행 불가"다.
- 상세 검색 시 메인 검색어 초기화
- 전체 검색 시 상세 조건 초기화

## 선택지
- 팝업 위치
  - A안 `DetailSearch`가 버튼·팝업·열림 상태를 모두 갖고, SearchBox는 그 자리를 slot(`detailSearch`)으로 받음: SearchBox는 검색어에만 집중, 팝업을 따로 테스트 / `onDetailSearchClick` prop 제거
  - B안 SearchBox가 팝업까지 포함: 페이지 코드가 가장 짧음 / SearchBox가 검색어·검색 기록·상세 검색을 모두 맡아 커짐
  - C안 페이지가 열림 상태 관리: 기존 props 유지 / 바깥 클릭 판단에서 버튼을 빼는 처리가 두 컴포넌트에 걸침
- 팝업을 열 때 메인 입력창 글자 옮기기: 옮기지 않음 / 옮김(다시 쓰지 않아도 됨, 어느 값을 옮길지 규칙 추가)
- 바깥 클릭·Esc·X로 닫을 때 쓰던 내용: 버림 / 유지(전체 검색 뒤 초기화를 따로 처리)

## 결정
팝업 위치 A안, 글자 옮기지 않음, 닫으면 버림. (사용자 선택)
- 페이지는 "지금 실행 중인 검색" 하나(전체 `{ query }` 또는 상세 `{ target, keyword }`)를 갖는다.
- 팝업은 열 때마다 페이지가 준 `defaultValue`로 시작한다. 실행 중인 상세 조건이 있으면 그 값이고, 없으면 제목과 빈 검색어다.
- 상세 검색을 하면 페이지가 메인 검색어를 비우고, 전체 검색을 하면 상세 조건을 비운다. 팝업은 다음에 열 때 자동으로 초기화된다. (Step 7)
- 팝업은 바깥을 누르면 닫히므로 두 입력창에 동시에 쓸 수 없다.
- [0027](0027-searchbox-controlled.md)의 `onDetailSearchClick`은 `detailSearch` slot으로 바뀐다.

## 결과
- 두 검색의 상호 초기화를 페이지 한 곳에서 처리한다.
- 팝업에 쓰다가 실수로 바깥을 누르면 쓰던 내용이 사라진다. 닫기는 취소로 본다.
- '검색하기'(312×36, 14px)는 기존 변형과 크기가 달라, 변형이 높이·글자·색을 정하는 규칙([0028](0028-button-no-padding.md))대로 `primary-small` 변형을 추가한다.
