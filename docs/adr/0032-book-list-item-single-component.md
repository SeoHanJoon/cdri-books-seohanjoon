# 0032. 접힌 행과 펼친 행을 expanded prop 하나의 컴포넌트로 합친다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 3, Step 4

## 배경
Step 2에서는 접힌 행 `BookListItem`과 펼친 행 `BookListItemDetail`을 따로 만들었다. ([0019](0019-book-view-type.md))
상세보기를 누르면 컴포넌트가 통째로 바뀌어 누른 버튼이 사라지고, 키보드 포커스가 `<body>`로 간다. 키보드 사용자는 목록 맨 앞부터 다시 Tab을 눌러야 한다.

## 선택지
- A안 두 컴포넌트 유지, 목록이 토글 뒤 새 버튼으로 포커스를 옮김: 기존 props 유지 / 버튼이 바뀌는 것을 코드로 덮음, 스크린리더는 다른 버튼으로 인식
- B안 `expanded` prop 하나의 컴포넌트: 상세보기 버튼이 같은 요소로 남아 포커스가 저절로 유지 / props·ADR 변경, 모바일에서 버튼 위치가 달라 CSS가 복잡해짐

## 결정
B안. (사용자 선택)
- props: `{ book, liked, expanded, onToggleLike, onToggleDetail }`. 0019의 "공통 props를 두 컴포넌트가 확장"을 대체한다. 화면용 `Book` 타입 결정은 그대로다.
- 상세보기 버튼은 HTML 맨 앞에 두고, 나머지 내용만 상태에 따라 바뀐다. "버튼 다음에 펼쳐지는 내용" 순서라 펼친 뒤 Tab이 바로 펼친 내용(하트 → 구매하기)으로 들어간다.
- 넓은 화면은 시안에서 두 상태의 버튼 위치가 같다(행 위 26px, 오른쪽 16px, 115×48). 좁은 화면 배치([0029](0029-book-row-responsive.md))는 CSS 순서로 그대로 유지한다.

## 결과
- 펼치고 접어도 포커스가 상세보기 버튼에 남는다. 브라우저 테스트로 지킨다.
- 접힌 행에서는 화면 맨 오른쪽의 상세보기가 Tab 순서로는 먼저 온다.
- 디자인이 그대로인지 `/dev/elements`를 1920px·375px에서 합치기 전과 픽셀 비교해 확인한다.
