# 0053. 찜 목록은 Book 배열로 저장하고, 찜 페이지에서 해제한 책은 떠날 때까지 남긴다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 8

## 배경
찜은 Zustand + persist로 저장하고([0005](0005-client-state-zustand.md)), 찜한 시점의 화면용 `Book`을 그대로 복사해 둔다([0019](0019-book-view-type.md)). 책은 `isbn`으로 구별한다([0031](0031-book-isbn-identifier.md)).
저장 모양, 목록 순서, 찜 페이지에서 하트를 끌 때의 동작, "10개 단위" 무한 스크롤을 만드는 방법은 시안에 없다.

## 선택지
- 저장 모양
  - A안 `books: Book[]`: 배열 순서가 곧 찜한 순서, 코드가 가장 짧음 / 찜 여부를 찾을 때 배열을 훑음
  - B안 `isbn → Book` 객체 + 순서 배열: 바로 찾음 / 두 값을 항상 같이 고쳐야 함
  - C안 `{ book, likedAt }[]`: 나중에 날짜 표시·정렬 변경이 쉬움 / 지금 쓰는 곳이 없음
- 목록 순서: 최근 찜한 책이 위 / 먼저 찜한 책이 위
- 찜 페이지에서 해제
  - A안 페이지에 있는 동안 행을 남기고 빈 하트로: 실수해도 다시 눌러 되살림, 행이 밀려 올라가지 않고 포커스도 남음 / 보여줄 목록을 페이지가 따로 들고 있어야 함
  - B안 바로 목록에서 뺌: 가장 단순, 건수와 행 수가 항상 같음 / 되살리려면 다시 검색해야 하고, 포커스가 페이지 맨 앞으로 감
- 10개 단위 무한 스크롤
  - A안 보여줄 개수를 10씩 늘림, 감지는 `LoadMoreFooter` 재사용([0049](0049-search-page-split.md)): 데이터가 이미 브라우저에 있어 로딩·에러가 없음
  - B안 `useInfiniteQuery`로 감쌈: 검색과 같은 모양 / 서버 데이터 도구에 브라우저 데이터를 넣어 0005의 역할 나누기와 어긋나고, 찜이 바뀔 때 캐시도 맞춰야 함

## 결정
모두 A안, 순서는 최근 찜한 책이 위. (사용자 선택)
- 찜은 수백 권이어도 배열을 훑는 비용이 작다. 페이지는 렌더링마다 isbn `Set`을 한 번 만들어 행마다 찾는다.
- 방금 찜한 책을 찜 페이지 맨 위에서 바로 확인할 수 있다. 검색 기록(최근 것이 맨 앞, [0050](0050-search-history-store.md))과도 같은 규칙이다.
- 찜 페이지는 들어올 때의 찜 목록을 보여줄 목록으로 잡고, 해제된 책도 그 자리에 빈 하트로 남긴다. 다시 누르면 원래 스냅샷 그대로 다시 찜한다. 건수 "찜한 책 총 N건"은 실제 찜 수라 바로 줄어든다. 다른 탭에서 새로 찜한 책은 맨 위에 더해진다. 탭을 옮겼다 돌아오면 해제한 책은 사라진다.
- 보여줄 개수를 10에서 시작해 목록 끝이 보이면 10씩 늘린다. 자르는 로직은 작은 훅으로 빼서 단위 테스트한다.

## 결과
- store는 `books`, `toggle(book)` 정도로 작고, 저장 형태가 바뀌면 `version`/`migrate`로 대응한다.
- 실수로 찜을 꺼도 페이지를 떠나기 전까지 되돌릴 수 있다. 대신 잠깐 동안 건수보다 보이는 행이 많을 수 있다.
- 찜 페이지는 요청이 없어서 스켈레톤·다시 시도 화면이 나오지 않는다.
