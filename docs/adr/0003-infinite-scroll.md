# 0003. 검색 결과와 찜 목록은 무한 스크롤로 10개씩 불러온다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 5, Step 8

## 배경
Figma 주석은 "페이지당 10개 아이템"만 명시하고, 다음 10개로 넘어가는 방식은 정하지 않았다. (디자인 유의사항: 명시되지 않은 요구사항은 지원자 판단)
시안에는 페이지 번호나 더보기 버튼 없이 목록이 이어진다는 표시(세로 점)만 있다.

## 선택지
- A안 무한 스크롤: 시안 그대로 추가 UI 없음, 탐색 흐름이 끊기지 않음 / 목록이 길어지면 렌더링 비용 증가, 특정 위치로 돌아가기 어려움
- B안 더보기 버튼: 사용자가 직접 조절 / 시안에 없는 버튼 추가
- C안 페이지 번호: 위치 파악 쉬움 / 시안에 없는 UI 추가, 카카오 API는 최대 50페이지까지만 조회 가능

## 결정
A안. 시안에 추가 UI가 없다는 점을 가장 중요하게 봤다.
검색 결과는 `useInfiniteQuery`로 페이지를 이어 붙이고, 응답의 `meta.is_end`로 다음 페이지 여부를 판단한다. 목록 끝은 IntersectionObserver로 감지한다.
찜 목록은 서버 조회가 없으므로 저장된 배열을 클라이언트에서 10개씩 잘라 같은 방식으로 보여준다.

## 결과
- 검색 결과와 찜 목록의 스크롤 경험이 같다.
- 목록이 수백 개로 길어지면 렌더링 비용이 커질 수 있다. Step 9에서 행 메모이제이션과 이미지 지연 로딩으로 대응하고, 필요하면 가상 스크롤을 검토한다.
