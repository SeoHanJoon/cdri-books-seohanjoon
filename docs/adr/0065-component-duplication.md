# 0065. 스켈레톤 행은 책 행과 배치 클래스를 같이 쓰고, 페이지 제목은 페이지가 그린다

- 상태: 채택
- 날짜: 2026-11-28
- 관련 Step: Step 11

## 배경
역할이나 디자인이 겹치는 컴포넌트를 점검했다.
1. `BookListSkeleton`의 행이 `BookListItem` 접힌 행의 배치 클래스(grid, lg 반응형)를 복사해 쓴다. 행 배치를 바꾸면 두 곳을 함께 고쳐야 하고, 지금은 e2e "스켈레톤 행은 책 행과 높이가 같다"만 이것을 지킨다.
2. 도서 검색의 `<h1>도서 검색</h1>`은 `SearchBox`가 그리고, 찜 페이지의 h1은 페이지가 그린다.
3. 아이콘만 있는 버튼 3곳(찜 하트, 검색 기록 X, 상세 검색 닫기 X)과 `NoData`·`ErrorMessage`도 모양이 비슷하다.

## 선택지
- 1: A안 배치 클래스를 상수로 같이 씀 / B안 행 틀 컴포넌트(표지·정보·가격·버튼 자리)를 만들어 둘 다 씀(BookListItem 구조가 크게 바뀜) / C안 유지
- 2: A안 제목을 SearchPage로 옮김 / B안 유지
- 3: A안 `IconButton`, 상태 안내 컴포넌트 하나로 합침 / B안 유지

## 결정
1-A, 2-A, 3-B. (사용자 선택)
1. 접힌 행의 자리별 배치 클래스를 `components/book/`의 상수로 두고, 책 행과 스켈레톤이 같이 쓴다. 바뀌는 곳이 작고, 두 행이 어긋날 수 없게 된다.
2. 제목은 두 페이지 모두 페이지가 그린다. `SearchBox`는 입력창과 검색 기록만 맡는다.
3. 아이콘 버튼 3곳은 위치·크기·`aria-pressed` 여부가 모두 달라 공통 부분이 `type="button"` 정도다. `NoData`(14줄)와 `ErrorMessage`(19줄)는 작고, 합치면 아이콘·버튼·`role="alert"` 분기가 생긴다. 둘 다 유지한다.

## 결과
- 책 행 배치를 고치면 스켈레톤도 함께 바뀐다.
- 페이지 제목이 어디 있는지 두 페이지에서 같다.
