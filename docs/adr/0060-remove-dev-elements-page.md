# 0060. 개발용 /dev/elements 화면을 지우고, 그 테스트는 실제 페이지로 옮긴다

- 상태: 채택
- 날짜: 2026-11-27
- 관련 Step: Step 9

## 배경
[0022](0022-dev-elements-page.md)는 Step 2에서 공통 컴포넌트를 Figma Elements와 나란히 비교하려고 `/dev/elements`를 만들었다. 지금은 모든 화면이 실제 페이지에 연결되어 비교할 일이 없다.
대신 브라우저 테스트 약 25개가 이 화면에서 돈다. 그중 일부는 실제 페이지 테스트에 없다: 할인가가 없을 때의 가격 표시, 펼친 뒤 포커스, 한글 조합 중 Enter, 검색 기록 드롭다운 닫기, 버튼 글자 줄바꿈.
MSW fixture 40권은 모두 할인가가 있어 도서 검색 페이지에서는 "할인가 없음"이 나오지 않는다.

## 선택지
- A안 실제 페이지로 옮기고 지움: 테스트가 사용자가 쓰는 화면을 확인함 / 옮기는 작업
- B안 화면과 테스트를 함께 지움: 가장 빠름 / 위 동작을 지키는 테스트가 사라짐
- C안 그대로 둠: 작업 없음 / 실제 화면과 따로 관리해야 하는 개발용 화면이 남음

## 결정
A안. (사용자 제안, 테스트 처리는 사용자 선택)
- 실제 페이지 테스트와 겹치는 것(구매하기 새 탭, 하트 토글 등)은 지운다.
- 나머지는 기능별 spec으로 옮긴다. 책 행·검색 입력은 `search.spec.ts`, 드롭다운은 `search-history.spec.ts`, 상세 검색은 `detail-search.spec.ts`.
- "할인가 없음"은 찜 페이지에서 확인한다. 테스트가 할인가 없는 책 스냅샷을 localStorage에 넣는다. 찜은 찜한 시점의 데이터를 그대로 보여 주므로 실제로 생길 수 있는 경우다. fixture는 실제 응답 그대로 둔다([0030](0030-fixture-real-response.md)).
- "검색이 한 번만 된다"는 화면의 검색 로그 대신 카카오 API 요청 수로 센다.

## 결과
- 개발 전용 라우트와 화면 코드가 없어진다.
- 공통 컴포넌트에 새 변형이 생기면 실제 페이지에서 그 경우를 만들어 확인해야 한다.
